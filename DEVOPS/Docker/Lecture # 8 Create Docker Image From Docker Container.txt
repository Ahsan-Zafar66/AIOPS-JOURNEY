Flow of Concept


Docker File ----> build command ---> docker image ---> run command --> docker container

we can create image from docker container using commit command

docker container --> commit command ---> docker image

docker commit command creates a docker image from docker container.

# syntax
docker commit container_name imagename:tag


Why we need to create an image from container?
Because whatever you do to create a docker file and we create image from docker file and docker image are non-writable.
So, there always some configuration that is left or it is needed, so what we do we run the image, which create container do the changes in container and use commit command to create a docker image from container.
In this way, our all needs are satisfied


whenever you make changes in a container, ceate image and push it in docker hub so that it is always available

When you change image name or tags image id remains same

image id chnages only when you make an image from a file and update the file and make a new image from it, now both images will have different image id because both files are different



Docker commit : It will be create docker image from docker container
