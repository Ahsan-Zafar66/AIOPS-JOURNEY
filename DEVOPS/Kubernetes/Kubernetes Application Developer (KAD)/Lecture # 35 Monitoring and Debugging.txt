Kubernetes Debuggng Tips:

1) Check Ibject Status: Check the basic status of objects (pods, deployment, service, replicaset and etc). This can be a quick way to locate a broken Pod in the cluster

2) Check Object Configuration: use kubectl describe and or view the full object manifest (yml file) o understand the relevant obkects in more detail

3) Check Logs Check container logs, and even cluster lovel logs, for more insights into what is going on

Metrics Server:
Single cluster has one metric server configuration.
you cannot configure multiple clusters with single metric server.

Metric server has in-memory solution, it has limitation that you cannot save results in an external disk

You cannot see historical metrics with metrics server, like yesterday metric, 7 days ago metircs, a month ago metrics. You cannot see historical metrics with metrics server.

For historical metrics, you can use disk base solutions.


kubernetes deploy a kubelet agent on each node in a cluster. kubelete provides complete information of a node to API server.
kubelete do everything inside a node.
deploying pods in a nodes and checking theri health is job of kubelet. 
API server orders kubelet that create this pod in your node, kubelete creates pod. 

kubelet has an internal component called cAdvisor, CAdvisor extract metrics of pod and node.

The kubelet componnet cAdvisor extract metrics about node and pod and send it to the metrics server using kubelet API.


metric server get the information from kubelet API, then aggregates the information, store it in memory and show the results
