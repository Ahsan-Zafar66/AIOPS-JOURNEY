What si service Account?
Consider service account like authorization of getting some information form kubernetes.
Suppose you work at google, you have your employee card, that employee card have access to some data and do not have acces to other data out of your range.
Now, using your employee card you can access certain things but cannot access other things for which you have no authorization.

Now, when we have appplication they use a lot of services, baanking service, cloud service , sshd , hhtpd, dashboard and a lot.

suppose you have kubernetes cluster and you need to make a dashboard of what is happening in kubernetes using python.
Now, python app needs to get data from kubernetes cluster throug request, now if python app has authorization of getting data from kubernetes then it will get it otherwise not.
Now, python is a service equesting data from kubernetes.
So, service accounts are dedicated to different services that have different privileges based on theri needs and they interact with kubernetes using their service account.
When python comes to kubernetes it says i need this data, kubernetes say show your service account or level of authorization you have  and then after checking authorization of python app kubernetes gives acces to python app.
So, in this way different serivices have different service accounts based on theri need, the same way different employees in a company managaers, it offices, ceos have theoir own card and privileges.




# command to create service account
kubectl create serviceaccount service_account_name

# when a service account is created a token is created with it.


# flow of things
service account creation --> service account object ---> token is create as a secret which has Role Based Acess Control Information (what this token can have or acess) --> you can describe token using its name

NOTE: if you need to use token outside of kubernetes cluster then you can export token
if you need to use it inside kubernetes cluster in a pod, you wil store the token in a volume and then mount this volume on the pod, the pod will automatically fetch token from the volume for process.


# when you create a service account you need to attach it with your pod

# example of creating a service account naem dashboard-sa
kubectl create serviceaccount dashboard-sa

# creating a pod and attaching the service account dashboard-sa
apiVersion: v1
kind: Pod
metadata:
  name: my-pod5
spec:
  containers:
  - name: container-pod
    image: my-kubernetes-dashboard
  serviceAccountName: dashboard-sa



# Step # 1 Create Pod
# Step # 2 Create Service
# Step # 3 Create Service Account
# Step # 4 Create a Role
# Step # 5 Create Role Binding
# STep # 6 create token in step # 3 service account
# Step # 7 Now use the token to see information on dashboard
