Seccomp stands for secure Computing Mode.

In Kubernetes, seccomp profiles are used to restrict syscalls made by containers. This reduces the kernel attack surface.
Kubernetes supports applying seccomp profiles:
At the pod level
Or container level



In linux or any OS we have a kernel layer and user layer.
At user layer you install aps such as chrome, vim, nano and etc.
The changes you made at user level such as open, close, write, read and etc they are done at kernel level because kernel is directly attached to hardware.

Seccomp in kubernetes restrics pods what they can request to kernel, so seccomp provides security at kernel level.

There are three types of profiles for seccomp you can use in kubernetes pods:
1) Unconfined: No restriction, a resource or pod can make any number of system calls to kernel
2) Default Runtime: Apply default moderate restrictions to resources, it is define at the time of cluster creation.
3) Custom Profiles: Custom Profile as three types:
	1) Audit Profile: Good for testing, to see what would be blocked without enforcing. whatever request or system call is made by pod for read, write, open, close and etc operations it is logged into base OS logs.
	2) Violation Profile: Deliberately blocks certain syscalls (to simulate policy violations). Used to test enforcement. Restrict Pod that made any request or violation os system call, it does not let the pod to be scheduled. Pod is not created and shows CrashLoopBackOff status
	3) fine-grained Profile: Designed to allow only the exact syscalls an app needs. This profile allows pod for making desired system call to kernel. It provides you power what sys call a pod can make and what cannot.


Seccomp Hands On in kind cluster:
# So, download all these three profiles in the directory you are working
# downloading and storing all three profiles in a directory called profile
mkdir ./profiles
curl -L -o profiles/audit.json https://k8s.io/examples/pods/security/seccomp/profiles/audit.json
curl -L -o profiles/violation.json https://k8s.io/examples/pods/security/seccomp/profiles/violation.json
curl -L -o profiles/fine-grained.json https://k8s.io/examples/pods/security/seccomp/profiles/fine-grained.json
ls profiles


# now create kind cluster and mount this directory in control plane node
apiVersion: kind.x-k8s.io/v1alpha4
kind: Cluster
nodes:
- role: control-plane
  extraMounts:
  - hostPath: "./profiles"
    containerPath: "/var/lib/kubelet/seccomp/profiles"

Now our profiles directory is mounted in control plane node at path "/var/lib/kubelet/seccomp/profiles"


Audit Profile:
# now you just need to make pod for audit profile
apiVersion: v1
kind: Pod
metadata:
  name: audit-pod
  labels:
    app: audit-pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: profiles/audit.json
  containers:
  - name: test-container
    image: hashicorp/http-echo:1.0
    args:
    - "-text=just made some syscalls!"
    securityContext:
      allowPrivilegeEscalation: false

# above pod will be scheduled on control plane as we have only one node and mapped the profiles in control plane by using mount.


# exposing above pod using a service, container port is 5678 and nodeport will be randomly given by kubernetes.
kubectl expose pod audit-pod --type NodePort --port 5678

# now open firefox and use nodeip:nodeport nodeport is not 5678, 5678 is container port, check service to get the nodeport

# now logs generated by above pod can be seen using following command
# The log path on your computer might be different from "/var/log/syslog"
tail -f /var/log/syslog | grep 'http-echo'

# in logs see for http-echo




Violation Profile:

# violation pod yml file
apiVersion: v1
kind: Pod
metadata:
  name: violation-pod
  labels:
    app: violation-pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: profiles/violation.json
  containers:
  - name: test-container
    image: hashicorp/http-echo:1.0
    args:
    - "-text=just made some syscalls!"
    securityContext:
      allowPrivilegeEscalation: false


# above pod will not be created and will end showing "CrashLoopBackOff", because violation profile is applied and pod is making violation so it will not be created


Fine-grained profile:

# yml file for fine-grained-pod
apiVersion: v1
kind: Pod
metadata:
  name: fine-pod
  labels:
    app: fine-pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: profiles/fine-grained.json
  containers:
  - name: test-container
    image: hashicorp/http-echo:1.0
    args:
    - "-text=just made some syscalls!"
    securityContext:
      allowPrivilegeEscalation: false

# above pod will be created and run.
# you need to check logs, no logs will be created for this pod as it has been given permission for syscall as we desire.


# expose pod using a service
kubectl expose pod fine-pod --type NodePort --port 5678

# 5678 is container port not nodeport, to access pod use
nodeip:nodeport

# The log path on your computer might be different from "/var/log/syslog"
tail -f /var/log/syslog | grep 'http-echo'



Kubernetes Kind Cluster with default seccomp profile:
# cluster-config.yml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    image: kindest/node:v1.28.0@sha256:9f3ff58f19dcf1a0611d11e8ac989fdb30a28f40f236f59f0bea31fb956ccf5c
    kubeadmConfigPatches:
      - |
        kind: JoinConfiguration
        nodeRegistration:
          kubeletExtraArgs:
            seccomp-default: "true"        
  - role: worker
    image: kindest/node:v1.28.0@sha256:9f3ff58f19dcf1a0611d11e8ac989fdb30a28f40f236f59f0bea31fb956ccf5c
    kubeadmConfigPatches:
      - |
        kind: JoinConfiguration
        nodeRegistration:
          kubeletExtraArgs:
            seccomp-default: "true"


# above cluster created will have default profile of seccomp applied on all resources created
