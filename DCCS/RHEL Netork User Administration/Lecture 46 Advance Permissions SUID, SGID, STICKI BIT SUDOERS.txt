SUID:
as we know that a file has users, group and others permissions
for example
-rw-r--r--

above file user have read and write, group has read and other also has read permission

now in user section if you see "S" --> SUID
if s is smalle == SUID + x (execute) permission is set
if S is capital == SUID only no execute permission


# settng suid with capital S
chmod u+s filename

#example
chmod u+s test

# seting suid with smaller s (execute perm as well)
chmod u+xs test

# taking or removing permission
chmod u-xs test


SGID:
in group section if you see "S" --> SGID
in group section if youu "s" --> SGID + execute permission

# giving the S 
chmod g+s test

# giving s
chmod g+xs test



STICKY BIT:
in others section if you see "t" --> Stickybit
t == Sticky bit is set with x permission
if T == Sticky bit without x permission

# giving T 
chmod o+t test

# giving t
chmod o+xt test



Setting advance permissions in octal way:
suid --> 4

sgid --> 2

stickybit --> 1

read -- > 4

write --> 2

execute --> 1


normal permissions:
chmod 777 test

advance permissions:
first word is for advance permissions and othe rthree are for normal permissions

chmod 4777 test --> suid and all normal

chmod 2777 test --> sgid and all normal

chmod 1777 test --> sticky bit and all normal

chmod 7777 test --> setting suid, sgid, stcky bit all with all  normal permissions




WHAT IS SUID:
SUID is used to give all users privilege to run commands that can be run only by root

there are commands that are only run by root like fdisk,
even though group and other users have execute permission they cannot run.

# REQUIREMENT is to enable the users to run fdisk
If we apply SUID on /sbin/fdisk then all users can run fdisk


# lets give fdisk SUID permissions so any user can use it
cd /sbin

chmod u+s fdisk


SUID is quite dangerous as all users can run root commands like fdisk. Now any one can make or remove partitions which is quite dangerous

NOW MY REQUIREMENT is to give access o only a desired user
Now in this situation SUID is not the solution.
Now we need to set sudoers

What is the difference b/w suid and sudoers?
suid --> provide access to all users
sudoers --> provide root privileges commands acess for specific users.


# which files has suid, how to find all suid files?
find / -perm -4000 -print --> find all the files with suid permission

find / -perm -2000 -print --> find all files with sgid permission

Sudoers:
vey important and alot of application in devops

Scenario:
 there is a developer who is asking access to star tot stop a service.
He is a normal user we are administrators we need to give him permission to start or stop the service

# tool used to edit sudoers file is visudo because it checks sysntax, errors
# the service let's suppose it is httpd

Step # 1 open sudoers file via visudo
visudo

Step # 2 write the following code
username command

# we are giving ahmed permission to run systemctl start httpd access, 
ahmed ALL=(ALL) NOPASSWD: /usr/bin/systemctl start httpd

# now when ahmed user runs following command he may not be required to enter administrator password and ahmed account password not needed 
sudo systemctl start httpd

but note: he can start the service as we entered in sudoers file but he cannot stop it, we need to enter the stop command as well



# now giving start, stop and restart permission to ahmed
ahmed ALL = (ALL) /usr/bin/systemtl start httpd, /usr/bin/systemctl stop httpd, /usr/bin/systemctl restart httpd


Now sudoers file will be difficult to maintain if you think on big scale giving access to each step separately.
In such situation we can make templates
in templates we define a set of commands and assign to users.

# syntax is to write Cmnd_ALias TEMPLATE_NAME_IN_CAPITALS = commands
Cmnd_Alias MYTEMPLATE = /usr/bin/systemctl start httpd, /usr/bin/systemctl stop httpd, /usr/bin/systemctl restart httpd

Now I can use my MYTEMPLATE for as many users as I like

now go into the bottom of visudo file

# assinging template 1 to user ahmed
ahmed ALL =(ALL) NOPASSWD: MYTEMPLATE
