# to install an rpm package
rpm -ivh package_name

# if package give dependency error you can istall by using nodeps keyword
prm -ivh --nodeps package_name

# getting information about rpm package
rpm -qi package_name

# checking that file is created by which package
rpm -qf /etc/fstab --> who created fstab x

# to see if a package is installed or not
rpm -qa | grep -i mysql --> -qa means query all and -i means ignore lettercase

# updating  an already installed package
yum update package_name

# checking report if update avaiable
yum check-update package_name


Scenario:
You installed mysql version 5.0 but the developer team need 5.7, you checked in yum the version available in yum is 5.
What you will do now?
You will go to internet find the repository fro mysql 5.7 and download it in your local system and paste it in /etc/yum.repos.d/ directory along with other repos
now you can install mysql 5.7 by updating or by removing previous and installing new one.

Suppose you didn't find the repository how you will install now?
You can install by downloading the code compilation

If the interviewer ask you that he wants to install a specific version of a software?
the best answer is that you will look for rpm for that version, ot repository of that version or source code compilation

# to see yum history
yum history


# not to see details about a process
yum history info 9 --> it will show the details of ID 9 which software was installed, let's suppose docker, it will show details of installation of docker

# reversing or roll backing installation
yum history rollback 7 --> take the machine back to installation of sotware at 7 id, and remove all other softwares having id more than 7

# removing only a specif package through id
yum history undo 7 --> suppose docker had id 7 now it will be removed
