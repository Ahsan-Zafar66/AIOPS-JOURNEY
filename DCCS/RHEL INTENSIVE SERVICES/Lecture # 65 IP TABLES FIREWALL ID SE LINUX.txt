# changing accept policy

I blocked all incoming, outgoing and moving forward permissions.


# now we will write a rule that if a client is coming for port 80 give it access else for any other port block it

WE MAKE RULES ON THE BASIS OF FRAMEWORK OF IP PACKET
# ip packet framework
sip dip dport

sip = source ip (client ip addres)
dip = destination ip (server ip address where service is hosted)
dport = destination port (service to acces on the server)

RULE: for allowing the client if it is coming for port 80
Input --dport 80 -j ACCEPT --> if the input port request is for 80 -j means jump and ACCEPT means accept (give accesss)


# allowing all clients to access port 80, as port 80 (httpd) uses tcp so we need to add it
iptables -A INPUT -s 0/0 -p tcp --dport 80 -j ACCEPT

# diagnosis of above command
iptables = refers to iptables
-A INPUT= append rule in INPUT chain
-s 0/0 = all clients (0/0 means all, if you want to allow a specific client write his ip)
-p tcp = tcp protocol
--dport 80 = if client asks for destination port (server port) 80
-j ACCEPT = jump and accept that client 



# opening ssh port for a client
iptables -A INPUT -s 192.168.43.63/32 -p tcp --dport 22 -j ACCEPT


# STATES in firewall
Established.
New.
Related.

If a person has connected with the server as he was allowed to connect but OUTPUT is blocked for all then he cannot go out after the connection of client and server on the mentioned port is established.

Now, we can allow only clients to move out whose connection was established with the server on any port. In this way we are allowing only the allowed clients to come on their respective ports and move out if they are able to establish a connection with server.

# command for allowing client with established connections to move out
iptables -A OUTPUT -d 0/0 -m state --state ESTABLISHED -j ACCEPT

# diagnosis of above command
iptables = refer to iptable

-A OUTPUT = append this rule for output chain
-d 0/0 = do for destination 0/0 any, any client from destination (means inside server)
-m state = match the state of client

--state ESTABLISHED = if the state of client is ESTABLISHED means he was allwoed to make a connection with server
-j ACCEPT = jump and ACCEPT

# opening ssh port for all clients
iptables -A INPUT -s 0/0 -p tcp --dport 22 -j ACCEPT

ssh ahsan@192.168.43.210 --> on second machine (192.168.43.63) run this command to connect to port 22 on 192.168.43.210 machine

# how to delete a rule from IPTABLE
iptables -D INPUT 2 --> delete rule 2 from INPUT chain

iptables = refer to iptable
-D = delete
INPUT = from input chain
2 = rule number 2

------------SELINUX------------
Selinux means security enhance linux.

selinux can be disabled and enabled. 

enable has two categories enforcing and permissive

enforcing has number --> 1 (enforcing means full block)
permissive has number --> 0 (it allows you move forward with warning)

to switch between permissive and enforcing you don't need to reboot system
to switch to disabled you need to reboot system


# file of selinuc
cat /etc/selinux/config --> selinux config files


# working of selinux
enforcing has two values on (1) and off(0) and it applies on services like ftp,sam,nfs
2nd enforcing is context value, we have to set a context set for directories and files



suppose if a client comes fot ftp service, in ftp config file it is allowed that if  aclient comes for home directory give hime access, but hehind ftp selinux is also present if in selinuc config file value is 0 it will block the client, client won;t be able to access ftp though ftp allows but selinux is not allowing so client will not be able to access it

program level = allow , os level (selinux) = not allow then you cannot access service.

# checking status or boolean value of selinux
getsebool -a

# chekcing boolean values fro ftp
getsebool -a | grep -i ftp


if program level permissions are given but selinux level permissions are turned off then client cannot do the things turned off by selinux.
